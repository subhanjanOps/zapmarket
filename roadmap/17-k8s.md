# Plan 17 — Kubernetes and Helm

**Effort:** L | **Impact:** H | **Depends on:** Plan 14 (CI/CD must be in place first)

## Context
Deployment is Docker Compose only. No k8s/Helm manifests exist. Not cloud-native deployable. This plan produces a production-grade Helm chart for all services.

## Scope
- Helm chart per service (or umbrella chart)
- ConfigMaps for non-secret config, Secrets for credentials
- HPA (Horizontal Pod Autoscaler) for stateless services
- PersistentVolumeClaims for PostgreSQL (or use managed RDS)
- Ingress for API gateway and UI apps

## Out of scope
- Service mesh (Istio/Linkerd) — future
- Multi-region deployment — future
- Managed Kafka (MSK) migration — future

## Tasks
- [ ] Create `infrastructure/helm/zapmarket/Chart.yaml` (apiVersion v2, type application)
- [ ] Create base `_helpers.tpl` with label selectors and naming conventions
- [ ] For each Go service: `Deployment` (2 replicas default), `Service` (ClusterIP), `HorizontalPodAutoscaler` (min 2, max 10, CPU 70%)
- [ ] For each Next.js UI: `Deployment` + `Service` + `Ingress` rule
- [ ] `ConfigMap` per service for non-secret env vars
- [ ] `Secret` per service for DB credentials, API keys (values injected from CI secrets, not committed)
- [ ] `Ingress` for api-gateway using nginx ingress controller
- [ ] PVC for PostgreSQL (or document external RDS connection)
- [ ] Add `helm lint` step to GitHub Actions CI (Plan 14)
- [ ] Add `helm upgrade --install --dry-run` step to CI
- [ ] Write `infrastructure/helm/README.md` with deploy commands

## Done criteria
- `helm lint zapmarket/` passes with zero errors
- `helm upgrade --install zapmarket . --dry-run` produces valid manifests
- Deploying to a local `kind` or `minikube` cluster brings up all services healthy
- HPA triggers scale-out on load test (k6 or hey)
