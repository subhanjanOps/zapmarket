## Fixed

| Bug | Severity | Fix |
|---|---|---|
| BUG-007: `/api/v1/skus` missing from gateway | Critical | Inserted route into `gateway_routes` live + added `0002_add_missing_routes.up.sql` migration. Also added `/api/v1/images`, `/v1/auth/me`, `/v1/auth/logout`, `/v1/admin`. |
| BUG-008/001: No admin can be created | Critical | (a) Seeded `admin@zapmarket.local / Admin@zapmarket1!` directly in live DB. (b) Added `0003_admin_bootstrap.up.sql` migration for future deploys. (c) Added `POST /v1/auth/admin/bootstrap` endpoint (env-var gated via `ADMIN_BOOTSTRAP_SECRET`) so first admin can be created without DB access. (d) Added `BootstrapAdmin` method to `AuthService`. |
| BUG-003: SKU UPDATE returns `product_id=00000000` | High | `sku_handler.go` `UpdateSKU` now re-fetches the full row via `GetSKUByID` after the update and returns that. |
| BUG-004: SKU CREATE/UPDATE return zero timestamps | Medium | Same fix as BUG-003 — re-fetch from DB. `CreateSKU` handler also now calls `GetSKUByID` after insert. |
| BUG-010: notification-service crashes on `inventory.reserved` | High | Changed `var payload map[string]string` to `var payload map[string]any` with string coercion — handles JSON numbers, booleans, and nulls in any event payload. |
| BUG-011: No template for `payment.processed` | Low | Added `payment.processed` case to `buildNotification` (dispatches same message as `payment.captured`). |
| BUG-006: Product lowercase status returns 500 | Medium | Added pgcode `23514` (check constraint violation) handler in `product_repository.go` `CreateProduct` — returns `400 INVALID_DATA` with "status must be one of DRAFT, ACTIVE, INACTIVE, ARCHIVED". |
| BUG-002: SKU GET nil UUID returns INVALID_DATA | Medium | Removed `uuid.Nil` guard from `sku_service.go` `GetSKUByID` — the DB lookup naturally returns `NOT_FOUND` for any UUID that doesn't exist. |
| BUG-005: `variant_attrs` vs `attributes` JSON tag | High | Tag changed to `attributes` in both `CreateSKURequest` and `UpdateSKURequest` to match what seller-ui sends. Swagger docs need regeneration (`swag init -g main.go` from the service dir). |

## Deferred

| Bug | Severity | Reason |
|---|---|---|
| BUG-009: No CORS on auth/catalog services directly | High | All frontend traffic is routed through the API gateway which handles CORS correctly. Direct-to-service calls are not an intended flow. Low risk in practice. |
| BUG-012: PENDING orders never expire | Medium | Requires a background expiry goroutine or saga compensation. Scope is broader than a bug fix — tracked for the order-management service roadmap. |
| BUG-013: Idempotency-Key body vs header | Low | Docs-only mismatch. Body field is the correct implementation. Remove `Idempotency-Key` from gateway CORS `Access-Control-Allow-Headers` if header approach is not used. |

**Change before production.** The `POST /v1/auth/admin/bootstrap` endpoint can also be used to create an admin if `ADMIN_BOOTSTRAP_SECRET` env var is set:

```bash
curl -X POST http://localhost:8000/v1/auth/admin/bootstrap \
  -H "Content-Type: application/json" \
  -d '{"secret":"<ADMIN_BOOTSTRAP_SECRET>","email":"you@example.com","password":"Strong1!","full_name":"Admin"}'
```
